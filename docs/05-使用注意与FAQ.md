# 使用注意与 FAQ

## 1. 三条最重要的注意事项

1. **进度是明文，存在 HTML 文件里。** 它跟着 iCloud / 绿联 NAS 一起同步。
   把这个 HTML 发给别人 = 把你的作答、笔记、批注一起发出去。这是「单文件闭环」的代价，知情即可。
2. **别在手机和电脑同时打开同一份 HTML 答题。** 首次打开会弹一次提示（之后收在底栏折叠菜单里），技术上也做了条目级合并，
   但两边同时改同一个文件仍可能丢东西。养成「一台答完再换」的習慣最省心。
3. **删文件就是删干净。** 没有附属进度文件、没有索引文件、没有 data.json（除非你手动开过调试日志）。
   同步软件云端的历史版本不归插件管。

## 2. 常见问题

### Q1 双击 .html 没反应 / 打开的是源码？
插件通过 `registerExtensions(['html'])` 接管了 `.html`。如果双击打开的不是本视图：
- 检查 `community-plugins.json` 里有没有 `html-single-file-view`
- 重启 Obsidian（社区插件只在启动时读取该文件）
- 或用命令面板 →「用 HTML 视图打开当前文件」
- 仍不行就用文件右键 →「用默认方式打开」退回系统浏览器

### Q2 进度没保存？
- 看底部状态条：显示「已保存 HH:MM:SS」才代表写盘成功
- 显示红色「保存失败」时，看提示原因（文件只读 / 被占用 / 体积过大）
- 插件默认 500ms 防抖自动保存，也可以点「保存进度」立即写

### Q3 页面顶部出现「当前不在自定义 HTML 视图，进度无法跨设备同步」
说明这个 HTML 不是在插件视图里打开的（比如用浏览器直接打开）。此时进度只落在
localStorage（沙箱下会退到内存），跨设备同步不了。回到 Obsidian 用本视图打开即可。

### Q4 手机上能同步吗？
可以，但前提是**同一个 HTML 文件**在两端都被同步覆盖。
- 插件在手机端同样工作（`isDesktopOnly: false`）
- 手机上答题 → 写回文件 → 同步软件把文件同步到电脑 → 电脑打开看到进度
- 前提是 Obsidian 在手机上打开了同一个 vault，且同步软件（iCloud / 绿联 NAS 同步）开着

### Q5 两台设备都改了同一份文件，会怎样？
插件在写回前会重读磁盘并做**条目级合并**：
- 同一题：比 `at` 时间戳，新的赢
- 笔记/评注/标记：按 `id` 合并，同 id 新的赢
- 删除用「墓碑」表达，会真正跨设备生效
合并后若保留了对方的修改，顶部会提示「已保留对方修改的 N 处」。

### Q6 数据区被改坏了怎么办？
插件发现 JSON 非法时会用新数据覆盖重建，并提示「进度数据区解析失败」。
常见原因：手改时把 JSON 语法搞坏了。

### Q7 为什么 HTML 顶部那段注释不能删？
它是给 AI Agent 的取数说明：数据在哪、怎么提取、字段什么含义。
删掉不影响功能，但 AI 就得全文扫一遍才知道进度在哪。

### Q8 页面里的「AI 提取说明」注释会不会让插件写坏文件？
不会。插件匹配数据区时会**跳过所有 HTML 注释**。
（这个坑我们踩过：最初正则会先命中注释里的字面量，一次写入就能把整篇文档吞掉。
现在有专门的回归测试盯着，见 `tests/progress-codec.test.mjs`。）

### Q9 能不能不用插件，只用浏览器？
可以，页面会降级到 localStorage。但：
- 进度只在本机，不会跟着文件同步
- 章节阅读进度、答题判分仍可用
- 页面顶部会明确提示「无法跨设备同步」

### Q10 插件会读我 vault 里的其他文件吗？
不会。插件只读写**当前视图正在打开的那一个 HTML**：
- 消息里不接受任何文件路径，目标恒为视图持有的文件
- 不提供通用 Vault 读写接口
- 不建索引、不扫全库

### Q11 页面里的 JS 能碰到 Obsidian 吗？
碰不到。iframe 的 sandbox 没有 `allow-same-origin`，页面处于 opaque origin：
读不了 Obsidian 的 DOM、拿不到任何凭据、localStorage 也直接抛错。
页面能做的只有：跑自己的 JS、把结果通过 postMessage 发回来。

### Q12 怎么给 AI Agent 用？
1. 把 HTML 文件路径告诉 Agent
2. 附上这段话：
   ```
   这份 HTML 的用户交互数据在文末 <script id="html-quiz-progress" type="application/json"> 块内，
   题目与标准答案在 <script id="html-content-meta" type="application/json"> 块内。
   请只解析这两块（各一次正则提取 + JSON.parse），不要通读正文。
   ```
3. 或者在 Obsidian 里点「复制复习清单」，直接得到一份现成的 Markdown 清单。

### Q13 手写标注怎么用？
1. 点右下角 `✏️` → 进入画笔模式（页面滚动锁定，工具条弹出）
2. 直接在正文上写：笔（Apple Pencil / S Pen / 手写笔）画，手指自动变成滚动
   - 工具条 `🖌` 选颜色（墨黑 / 红 / 荧光黄 / 蓝）与粗细（细 / 中 / 粗）
   - 工具条 `🎯` = 强制笔模式；`☝` = 临时放开滚动；`⠿` 拖动可吸附到四边
3. 写错了：`🩹` 橡皮点一下要删的那笔；`🧹` 单击清掉全部临时涂鸦
4. 满意了点 `💾 保存涂鸦` → 才真正写进 HTML 文件（跨设备同步）
5. `🧹` 双击并确认 → 连已保存的涂鸦一起清掉（会同步到其他设备）

**临时涂稿不会自动落盘**：画笔模式下防抖自动保存是关的，退出画笔模式时若还有未保存的笔，
会弹窗问你要不要保存。不保存就丢了——这是刻意的，避免误涂把文件搞脏。

### Q14 手写涂鸦会同步到手机吗？
会。它和答题进度走同一条通道（同一个 `strokes[]` 数组，同一份文件）。
笔迹用**段落锚点**定位（记下"画在哪个块 + 相对偏移"），换设备后版面宽度不同也能贴着原段落。

### Q15 为什么双击正文会放大？
画笔模式下双击 = 放大（不是选中文字），点以点击处为锚放大到 2x，再双击立刻回到 1x；
图片双击则是「等宽 → 全屏」。放大态右上角常驻 `⤢ 200%` +「还原」按钮，防止误触卡住。

### Q16 我没有触控笔，能用吗？
能。没有任何笔时手指就是画笔（页面滚动会被锁住，用工具条 `☝` 临时放开）。
如果你有笔但系统把它报成触摸（部分被动电容笔会这样），点工具条 `🎯` 强制笔模式即可。

### Q17 翻页键在哪儿？长什么样？
在页面**右侧垂直居中**的位置，两个上下三角（`▲` `▼`），透明度 40%，
两个箭头之间留了 44px（一个大拇指宽）的间隔，方便拇指分别按上下。
- 点一下：瞬时翻一屏（**没有滑动动画**，墨水屏设备上也不闪）
- 拖动它可以换位置，位置会跟着进度同步
- **触屏**：点按页面**上半屏**向上翻、**下半屏**向下翻；手指**滑动**仍然是正常滚动
- 画笔模式下不参与分区翻页（触摸用于画画或跟手滚动）

### Q18 顶栏去哪了？状态怎么看？
顶栏取消了，所有状态并到底栏一行：

```
‹   已保存于 23:05:20 · 保留了对方修改 3 处
```

- `‹` 是折叠键，点开是低频操作菜单：**重新加载文件 / 复制复习清单 / 使用说明**，
  菜单里还显示当前文件名和「别在多设备同时开」的提醒（首次打开文件时也会弹一次）
- 「保留了对方修改 N 处」= 这次保存合并了对方（另一台设备）的 N 处内容，不是你的改动
- 正文里**不再弹**黑色的「已保存」提示框，不打断阅读

### Q19 重启 Obsidian 后，HTML 标签页空了 / 标签越开越多？
v1.2.0 已修。

- **标签页空了**：视图没有把文件路径写进视图状态，重启恢复工作区时就丢了。现在会持久化路径，
  重启后标签页还是原来那个文件。
- **标签越开越多**：插件原先只在「已实例化的视图」里找已有标签页，找不到就新建一个。
  重启后没激活过的标签页只有存根、找不到 → 每开一次多一个标签页。
  现在改成先看视图实例、再看标签页的视图状态，按路径复用。
- **「重新加载文件」会不会把旧数据写回来**：不会。换页瞬间旧文档卸载时触发的保存会被按住，
  等新页面握手后才放行（见 [docs/03 §6.6 第 10 条](./03-部署与实机测试步骤.md)）。

如果你现在的 Obsidian 里已经堆了很多空标签页，把本插件的标签页全关掉再重新打开文件即可。

### Q20 我从外面下载的 HTML，打开后没有翻页键也没有标注按钮？
v1.3.0 已修。

页面侧的所有功能（翻页键、触屏分区翻页、标注、笔记、标记、手写涂鸦、进度回写）
都来自嵌在 HTML 里的 **runtime**。模板生成的页面自带 runtime，
外面拿来的普通网页没有，所以一个功能都起不来。

现在插件会在**渲染时自动注入**一份 runtime，所以：

- 任何单文件 HTML 用 Obsidian 打开，立刻就有全部功能
- **你的原文件不会因此变样**（注入只发生在内存里的渲染结果上）
- 磁盘上只会多一个进度区（你第一次做标注/作答时自动写入），这是跨设备接力必须的

正文容器建议用 `<main id="content">`；没有的话插件会退到 `<main>` → `<article>` → `<body>`，
退到 body 时会排除导航栏里的元素，标注不会锚到目录上。
生成规范见 [docs/07-AI生成HTML适配指引.md](./07-AI生成HTML适配指引.md)。

### Q21 右侧那条「笔记」竖条是什么？
笔记与标注面板的把手（v1.3.0 起）。

早先「我的笔记与标注」是直接插在正文里的，会挤占正文宽度——
在网格布局的页面上甚至被排到右边一列去。现在改成悬浮面板：

- 平时收起，右侧只留一条 18px 的窄把手，**完全不占正文宽度**
- 点一下从右边滑出面板，里面是新笔记 / 标记此处 / 保存进度 + 已有的条目
- 面板打开后把手挪到面板左边缘变成 ✕，点它收起；按 ESC 也能关

### Q22 用坚果云同步时，标注会不会把整个 HTML 重新传一遍？

**会。** 这是当前架构下无法绕开的事实，值得先知道。

坚果云同步插件走的是 WebDAV，每次上传都是**整文件 PUT**（没有分块、没有差分、没有压缩）。
所以**一次标注 = 一次整个文件的上传**。一个 3.5 MB 的 HTML，标 15 次就是约 52 MB 上行。

好消息是（真机实测，见 [docs/08](./docs/08-同步流量核查与写回策略.md)）：

| 动作 | 上传次数 |
|---|---|
| 打开文件看一眼 | **0** |
| 关闭文件 | **0** |
| 500 毫秒内的连续操作 | 合并成 **1** 次 |
| 滚动读完一篇 | **1** 次（只在跨章节时） |
| 一条一条慢慢标注 | **每次 1 次** ← 流量大头在这 |

也就是说，**「只看不改」完全不产生流量**，真正吃流量的是密集标注。

如果你要减少流量，最直接的三条路：

1. 插件设置里把「写回时机」改成**合并延迟**（连续标注合并成一次写盘）
2. 把 `nutstore-sync` 的 `skipLargeFiles.maxSize` 调小，大 HTML 不同步
   （代价：大文件失去跨设备接力）
3. 换用支持块级差分的同步方式（坚果云桌面客户端的「同步文件夹」模式）

### Q23 进度数据会不会把 HTML 弄脏 / 分享出去带进度？

会，这是设计使然。

进度写在 HTML 文件末尾的 `<script id="html-quiz-progress" type="application/json">` 里，
**不产生任何附属文件**。代价是：

- 文件字节数会变（几百字节到几 KB）
- 别人拿到你的 HTML，也就能拿到你的笔记和标注（明文）

如果你要的是「文件保持干净、进度另存」，那就得让进度单独存一份小文件——
但那违背了「零附属文件」的设计前提，目前没做。需要的话可以另开一轮。

## 3. 已知限制（🟡 黄灯项）

| 项 | 状态 | 说明 |
|---|---|---|
| 移动端真机 | **未实测** | 本机无 iOS / Android 设备。代码走 `vault.read/modify`（移动端安全）、无 Node API、`isDesktopOnly:false`，但没在真机上跑过 |
| UI 截图证据 | **未采集** | 测试期间 macOS 会话处于锁屏，系统禁止截屏。文件层与消息层证据齐全（G5 15/15、G6 26/26、G7 25/25），UI 截图待解锁后用 `scripts/capture-screenshots.sh` 补 |
| 手写笔硬件 | **无硬件可验** | 本机无触控笔。笔路径用 Chrome DevTools Protocol 向真实 Obsidian 派发 `Input.dispatchMouseEvent({pointerType:"pen"})` 验证（26/26 通过）；压感/笔锋明确不做 |
| 手写层移动端 | **未实测** | 依赖 Pointer Events（iPadOS 13+ Safari / Android Chrome 支持，Obsidian 移动端为 Chromium 内核 Capacitor WebView），但没在真机上跑过 |
| 鸿蒙 | **取决于宿主** | Obsidian 无官方鸿蒙原生客户端。能装 Android 版的鸿蒙设备仅实验性，HarmonyOS NEXT 无客户端 |
| 超大文件 | **未压测** | 30MB 以上 base64 图片的单页，移动端内存压力未量化 |
| 浏览器兼容 | **部分未验** | 只在 Electron/Chromium（Obsidian）与 jsdom 里验证过；Firefox / Safari 未验 |
| Obsidian CLI | **未启用** | 本机 CLI 未开，实机验收改用 `obsidian://` 自定义协议通道，不依赖键盘模拟 |
