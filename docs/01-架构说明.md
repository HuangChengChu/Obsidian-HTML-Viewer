# 架构说明 · Obsidian 单文件 HTML 视图插件

> 一句话：**让 HTML 文件自己携带状态**，Obsidian 只负责给它一个能跑 JS 的窗口和一条「把进度写回文件」的路。

---

## 1. 全景

```
┌─ Obsidian（桌面 / 移动，同一套代码）──────────────────────────┐
│                                                             │
│  插件 html-single-file-view                                  │
│  ├─ 视图类型 html-single-file-view                            │
│  │   └─ iframe  sandbox="allow-scripts allow-forms …"        │
│  │        ★ 不给 allow-same-origin → 页面在 opaque origin     │
│  │          跑，拿不到 Obsidian 的 DOM / 凭据 / localStorage    │
│  │                                                            │
│  ├─ postMessage 通道（白名单 + source 校验）                   │
│  │     iframe → 插件 : LOAD_PROGRESS / SAVE_PROGRESS          │
│  │     插件 → iframe : HTML_QUIZ:PROGRESS / ACK / SELFTEST     │
│  │                                                            │
│  ├─ 写回：vault.read(当前文件) → 文本手术 → vault.modify        │
│  │        ★ 只碰这一个文件，消息无法指定别的路径                │
│  │                                                            │
│  └─ 并发：每文件互斥锁 + 条目级合并 + 冲突提示 + 墓碑删除       │
│                                                             │
│  HTML 文件（单文件闭环）                                       │
│  ├─ <article id="content">            正文（AI 生成）           │
│  ├─ <section id="html-interaction-zone">我的笔记/批注（运行时渲染）│
│  ├─ <script id="html-content-meta">   题库 + 标准答案 + 章节结构 │
│  └─ <script id="html-quiz-progress">  ★ 唯一真相源（插件只写它）  │
│       { answers, notes, annotations, marks, sectionProgress … } │
└─────────────────────────────────────────────────────────────┘
        ↕ 同步软件（iCloud / 绿联 NAS）
   手机答题 → 文件被改写 → 同步到电脑 → 电脑打开，进度原样在
```

---

## 2. 三层职责

| 层 | 负责 | 不负责 |
|---|---|---|
| **插件**（Obsidian 侧） | 提供 iframe 窗口、收发消息、读写**当前这一个文件**、合并冲突 | 不认识「题」「笔记」「章节」是什么，只按契约搬数据 |
| **运行时**（页面内 JS） | 采集用户产出（答案/思路/评注/标记/笔记）、渲染可见区、图片与翻页交互、降级兜底 | 不直接碰文件系统 |
| **文件** | 既是内容载体，又是状态载体 | —— |

> 关键设计：**插件是「搬运工」不是「管家」**。派生判断（对错、复习清单、分类建议）都不落盘，交给页面或 AI Agent 现算，数据区只存原始用户输入。

## 3. 两条数据链

**读**
```
iframe 加载 → 发 LOAD_PROGRESS
            → 插件读文件 → 提取 <script id="html-quiz-progress"> 里的 JSON
            → 回 HTML_QUIZ:PROGRESS { payload }
            → 页面恢复：当前题号 / 已选项 / 滚动位置 / 章节进度 / 笔记 / 标注 / 翻页键位置
```

**写**
```
用户交互 → 运行时更新内存 → 500ms 防抖 → 发 SAVE_PROGRESS { payload }
        → 插件取本文件锁 → 重读磁盘 → 与磁盘版**条目级合并** → 文本手术 → vault.modify
        → 回 ACK → 页面显示「已保存 HH:MM:SS」
```

**降级**（不在插件里打开时）
```
600ms 内没收到插件回应 → localStorage（opaque origin 下抛错则退内存）
→ 顶部横幅「当前不在自定义 HTML 视图，进度无法跨设备同步」
```

## 4. 安全模型

| 威胁 | 防线 |
|---|---|
| 页面脚本偷 Obsidian 数据 | 不给 `allow-same-origin` → 页面在 opaque origin，跨源访问全部被浏览器拦 |
| 页面把 Obsidian 导航走 | sandbox 不给 `allow-top-navigation` |
| 外部网页/扩展伪造消息 | 只认 `event.source === iframe.contentWindow`，且指令走白名单 |
| 消息指定任意文件路径 | 目标文件恒为视图持有的 `this.file`，消息里不接受路径 |
| 恶意载荷撑爆内存 | 载荷必须是普通对象、序列化 ≤2MB、深度 ≤8、丢弃 `__` 前缀键 |
| 页面里的 HTML 注入 | 写入前对 `</script`、`<script`、`<!--` 三处做 JSON 安全转义 |

## 5. 交付物

```
~/Downloads/Obsidian-HTML-Viewer/
├── docs/     01 架构说明 · 02 实现设计 · 03 部署与实机测试 · 04 数据契约与提示词 · 05 FAQ
├── plugin/   插件源码（main.ts / manifest.json / versions.json / styles.css / 构建脚本）
├── templates/成品模板：资讯页 + 答题页（内置运行时 + 数据区占位 + AI 提取说明）
├── dist/     构建产物：dist/plugin/{main.js, manifest.json, styles.css}（直接拷进 vault）
├── tests/    纯函数单测 + 验收脚本
└── scripts/  一键构建模板 / 一键安装到 vault
```

安装后 vault 侧只多两样：`.obsidian/plugins/html-single-file-view/`（插件）和 `HTML视图测试/`（样例页）。**没有数据文件、没有索引文件**——删掉一个 HTML 就彻底干净。

## 6. 关键决策索引

36 条决策的完整表格与依据见 [02-实现设计.md §1](./02-实现设计.md)。最影响体验的五条：

| 决策 | 后果 |
|---|---|
| 数据区占位原地替换 | 同步软件每次只看到几行 JSON 变化，不产生整文件噪声 |
| 不给 `allow-same-origin` | 页面彻底碰不到 Obsidian，但页面里 localStorage 会抛错（已做降级） |
| 条目级合并 + 墓碑 | 手机删掉的误标，电脑上也会消失 |
| 章节级阅读进度 | 合集型长文档能标出「哪几章读完了」 |
| 只存原始输入，不存派生 | AI Agent 拿到的永远是用户真实产出，统计口径不漂 |
