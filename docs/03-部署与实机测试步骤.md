# 部署与实机测试步骤

> 本文件记录**已实际执行**的安装、启用、验证流程，以及每一步的可复现命令。
> 验收脚本：`scripts/verify-real.mjs`（在真实 Obsidian 进程里跑，不接受模拟）。

## 1. 安装（macOS / Windows / Linux 通用）

### 1.1 构建产物（如果你是从源码开始）

```bash
cd ~/Downloads/Obsidian-HTML-Viewer
npm install          # 根目录：jsdom（测试用）
npm --prefix plugin install   # 插件目录：esbuild / typescript / obsidian 类型
npm run build:all    # 构建模板 + 打包插件
```

产物：

```
dist/plugin/main.js       ← 插件主体
dist/plugin/manifest.json ← 插件清单
dist/plugin/styles.css    ← 视图外壳样式
templates/template-news.html  ← 资讯页成品模板（单文件）
templates/template-quiz.html  ← 答题页成品模板（单文件）
```

### 1.2 一键安装到 vault

```bash
./scripts/install-to-vault.sh "/Users/mac/Documents/Obsidian Vault"
```

脚本做三件事：
1. 复制 `dist/plugin/*` → `<vault>/.obsidian/plugins/html-single-file-view/`
2. 把 `html-single-file-view` 追加进 `<vault>/.obsidian/community-plugins.json`（**启用插件**）
3. 铺两份样例页到 `<vault>/html-view-test/`

### 1.3 让 Obsidian 加载插件

社区插件只有在 Obsidian **启动时**才会读取 `community-plugins.json`，所以必须重启：

```bash
osascript -e 'tell application "Obsidian" to quit' && sleep 4 && open -a Obsidian
```

> 手动路径：设置 → 常规 → 重新加载应用（Cmd+R）。

### 1.4 手机端

插件 `isDesktopOnly: false`，iOS / Android 的 Obsidian 同样可用。手机端不需要额外操作，
只要**同一个 HTML 文件**在两端都被同步软件（iCloud / 绿联 NAS 同步）覆盖即可。

## 2. 日常使用

| 操作 | 路径 |
|---|---|
| 打开一个 HTML | 双击 vault 里的 `.html` 文件（插件已接管该扩展名） |
| 退回系统默认打开 | 文件右键 → 「用默认方式打开」 |
| 复制复习清单 | 视图底部状态条 → 「复制复习清单」（或命令面板：复制当前 HTML 的复习清单） |
| 刷新页面 | 视图底部 → 「刷新页面」 |
| 清理已删除条目（墓碑） | 命令面板 → 「清理 HTML 进度里的已删除条目」 |
| 打开使用说明 | 命令面板 → 「切换 HTML 视图使用说明」 |

**无人值守入口**（可用于自动化 / 脚本）：

```
obsidian://html-view?do=selftest&vault=<库名>&file=<库内路径>   # 跑一遍脚本化自检
obsidian://html-view?do=probe&file=<库内路径>                   # 索要页面当前状态（并强制重载）
obsidian://html-view?do=review&file=<库内路径>                  # 复制复习清单
obsidian://html-view?do=clean&file=<库内路径>                   # 清理墓碑条目
obsidian://html-view?do=debug&enable=1                         # 开启调试日志
```

> 注意：子动作必须放在 `do=` 查询参数里。写成 `obsidian://html-view/selftest?...` 不会生效——
> Obsidian 的 URI 只把 query 部分交给 handler。

## 4. 实机测试抓到的三个「代码级测试抓不到」的缺陷（已修）

记录在这里，是因为它们正是「必须在真 Obsidian 里跑一遍」的价值所在：

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | 模板顶部「AI 提取说明」注释里写了字面量 `<script id="html-quiz-progress">` | **插件正则会先匹配到注释**，一旦写入就会把从注释处到真实数据块之间的整篇文档（head/style/body/正文）全部覆盖掉 | 匹配前先剔除 HTML 注释区间；注释里的提取正则同时收紧为带 `type="application/json"` 的形式，AI 侧用同样的正则也不会踩坑 |
| 2 | `setState` 早于 `onOpen`，iframe 尚未创建时就把 HTML 丢了 | 页面永远空白、握手不发生、进度不落盘 | 缓存已读文本，iframe 就绪时补渲染 |
| 3 | 沙箱 iframe 可能跨进程，`event.source === iframe.contentWindow` 不一定成立 | 消息被全部丢弃，插件看起来「没反应」 | 改为「一次性令牌 + source」双校验，令牌脚本注入在页面脚本之前 |

另有 2 个协议层细节：`obsidian://` 的子动作必须走 `do=` 查询参数；沙箱 opaque origin 下
`localStorage` 会抛错，模板里所有 localStorage 访问都做了 try/catch + 内存兜底。

## 5. 实机验收（G6，手写标注层）

### 5.1 为什么需要调试端口

手写层的「笔」必须用**真的笔事件**验证（本机没有触控笔）。做法是：
用 Chrome DevTools Protocol 向**真实 Obsidian 进程**里的沙箱 iframe 派发
`Input.dispatchMouseEvent({ pointerType: "pen" })`——这不是模拟 JS 事件，
而是走浏览器真实的输入管线，页面收到的就是货真价实的 `pointerdown`（`pointerType === "pen"`）。

Obsidian 是 Electron 应用，所以只要加一个启动参数即可：

```bash
osascript -e 'tell application "Obsidian" to quit' && sleep 4
open -a Obsidian --args --remote-debugging-port=9333 && sleep 10
node scripts/verify-ink-real.mjs "/Users/mac/Documents/Obsidian Vault"
```

> ⚠️ 这是**启动方式**的改动（多一个调试端口），不改动任何配置与数据。
> 验收完可以直接按平时方式启动 Obsidian，端口即失效。

### 5.2 脚本做了什么

1. 把样例页复位成干净模板，强制 Obsidian 重载页面
2. 通过 CDP 挂上 Obsidian 主页面 session，并找到 HTML 视图的**沙箱 iframe**（OOPIF，独立目标）session
3. 用**真实鼠标事件**点右下角 `✏️` → 进入画笔模式
4. 用**真实笔事件**在正文段落上划一笔（`pointerType: "pen"`）
5. 用真实触摸事件验证「识别到笔之后手指只滚动、不落笔」
6. 真实点击 `💾` 保存 → **直接校验 vault 里文件的字节**：笔迹条目、锚点、除数据区外逐字节未变
7. 重新打开页面 → 验证笔迹自动恢复并重绘
8. 真实双击正文 → 验证 2x 放大 / 再双击回 1x
9. 真实单击 `🧹` → 只清临时草稿；真实双击 `🧹` → 确认框 → 已保存笔迹写墓碑

### 6.4 触屏落点的判定规则（实测确认）

触屏分区翻页只认「**点按**」，落点必须同时满足四条，缺一不翻：

| 条件 | 判定 |
|---|---|
| 位移 | `|Δx| ≤ 10px` 且 `|Δy| ≤ 10px`（超了就是滑动，交给原生滚动） |
| 时长 | `≤ 400ms` |
| 落点 | 不是交互元素（`a / button / input / textarea / select / label / summary / details / contenteditable / 翻页键 / 手写工具条 …`） |
| 选区 | 当前没有选中文本 |

其中「落点不是交互元素」最容易被忽略：**答题选项是用 `label` 包的，点它是「选答案」，
不是「翻页」**。首轮验收脚本固定点 `(300, 120)`，正好落在选项 D 上，于是「上半屏翻页」被判失败——
查下来是**规则在起作用、测试选错了点**，不是代码坏了。现在脚本会先在页面里扫一个
「非交互落点」再点，并且把「点选项不翻页」单独列成一条断言锁死。

### 6.5 G7 抓到的缺陷（已修）

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 6 | `pointerdown` 里的 `setPointerCapture` 按 Pointer Events 规范会把 `click` 的 target **重定向到 pager 容器本身**，`e.target.closest("[data-hvv-dir]")` 恒为 null | **翻页键从上线起一次都没生效过**（用户实测「点了没反应」） | 方向在 `pointerdown` 时就记下来，click 时用它，不再依赖 target 反查 |
| 7 | 翻页键在右下角 `right:24px`，与手写 FAB（`right:18px`, 44×44, z-index 78）**完全重叠** | 「下一页」按钮被 ✏️ 压得一点不剩，用户以为没有翻页键 | 翻页键改为右侧垂直居中，与右下角 FAB 垂直错开 |
| 8 | 拖动结束后写回进度时读的是**旧的状态值**而不是刚拖出来的 style | 拖动位置不生效 | 改为读 `pager.style.top/right` |
| 9 | 旧版 `ui.pager = {x,y}` 迁移时把 `x` 丢了 | 老文件的翻页键位置丢失 | 迁移时 `right` 缺失则回退取 `x` |

> 第 6 条再次印证：**这类问题只有真机 + 真实输入事件才暴露得了**，
> 单测和静态检查都发现不了「click 的 target 被重定向」这种规范级行为。

### 6.6 收尾复验时抓到的缺陷（已修）

这一批是「代码写完 → 反复复验 → 把机器恢复到交付状态」的过程中才暴露的，
共同点是：**单次跑都过，连着跑或换个环境就出问题**。

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 10 | 换 iframe 时旧文档卸载，触发它的 `beforeunload` → 把**已经过期的内存态**保存回文件；合并逻辑再按 id 并集回来 | 旧数据「复活」；连着跑两遍验收，第二遍就失败（笔记数 2 → 4） | 换页期间按住页面发来的保存请求，等新页面握手（`LOAD_PROGRESS`）再放行（D41） |
| 11 | HTML 视图**没有把文件路径写进视图状态**，Obsidian 重启恢复工作区时标签页全变空；且 `openFileInView` 只按「已实例化的视图」找已有标签页，找不到就新建 | 重启后要重新打开文件；每开一次多一个标签页（本机一度堆到 **30 个**） | `getState()` 返回 `{path}`；查找标签页时先看视图实例、再看标签页的视图状态（D42/D43） |
| 12 | 补上 `getState()` 后，Obsidian 每次调整工作区布局都会重下视图状态 → 触发整页重载 | iframe 被反复换掉，页面里的滚动位置和未保存内容被冲掉；G6 直接超时 | `setState` 幂等：路径相同就不重载（D42） |

| 15 | 验收脚本跑完把 `auto-*` 样例页的标签页留在工作区里 | 用户的标签页越堆越多（和缺陷 11 同一个病根） | 脚本收尾只 detach 路径含 `html-view-test/auto-` 的 HTML 视图，用户的 `demo-*` 一律不动（D52） |
| 16 | **CDP 触摸事件的坐标系会变**：沙箱 iframe 被拆到独立进程时，触摸走浏览器进程 → 用「顶层窗口坐标」（要加 iframe 在主窗口的偏移）；同进程时用「iframe 内部坐标」（原样发）。同一台机器上两种都出现过 | 写死偏移后，G7 隔一阵子就飘一次：落点被整体平移 294/90，跨过了「上下半屏」分界线，于是「点选项应不翻页却翻了」「点下半屏却向上翻」 | 验收脚本**现场校准**：先发一个探针触点，回读页面收到的 `clientX/clientY`，用差值修正后续所有派发（D51） |

> 第 16 条值得单独说一句：**同一个脚本、同一个机器，两次跑的坐标系不一样**。
> 这不是玄学——iframe 被拆到独立进程（OOPIF）还是留在同进程，会改变输入事件的路由路径。
> 所以这里不能用「写死一个偏移」糊过去，必须让脚本自己测出来。
> 探针脚本留在 `scripts/probe-touch-coord.mjs`，随时可以复现。

### 6.7 触摸坐标系校准原理（实测确认）

```
发送坐标 = 目标局部坐标 + (探针发送值 - 页面收到的值)
```

探针点选在「两种坐标系解释下都落在 iframe 内」的位置，所以无论当前是哪种约定都能收到事件；
收到之后：

- 页面回传值 == 发送值 → 当前是「iframe 内部坐标」，偏移 = (0, 0)
- 页面回传值 == 发送值 − (294, 90) → 当前是「顶层窗口坐标」，偏移 = (294, 90)

本机实测（Obsidian 1.12.7 / Electron 39 / Chrome 142）**当前是「顶层窗口坐标」**，
iframe 在主窗口里的位置是 `left=293.5, top=90.09`。
而鼠标事件（`Input.dispatchMouseEvent`）两种情况下都是「iframe 内部坐标」，**不需要偏移**——
这个不对称是 Chrome 输入管线的既有行为，不是本项目的问题。

> 第 10 / 13 条的教训是一致的：**验收脚本自己也得有验收**。
> 「跑一遍绿」不等于「可重复」，所以 G5 现在要连跑三遍才算数。

| # | 缺陷 | 后果 | 修法 |

| 21 | page 宿主下 `setupInk()` 会对还没建立的画布调 `addEventListener` | **`init()` 中途抛异常**，后面的代码全不执行：关停按钮没建、画布没建，而且**页面不报任何错**，看起来只是"没反应" | 画布的指针事件挪进 `ensureInkLayer()`（跟着层走）；`init()` 外面包一层 try/catch，异常打到控制台并冒泡（D62） |

> 只能在 runtime 内部自己盯着 DOM。这是这一轮最花时间的地方。
